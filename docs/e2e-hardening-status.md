# E2E Hardening Status

QtNetworkChat treats the server as a transparent carrier for private-message E2E envelopes, identity announcements, and rotation control messages. Trust decisions remain local to the client.

## Completed Boundaries

- Authenticated identity-bound agreement using signed request/response transcripts.
- Persistent local E2E identity material, observed peer fingerprints, trust pins, mismatch handling, and cross-device short-code verification.
- Default trust gates for private text and private files.
- History metadata migration for `plaintext`, `encrypted`, and `decrypt-failed` states.
- Private file payload encryption before chunk upload, including Redis/object routing evidence that avoids Redis plaintext or session keys.
- Encrypted private file same-wire cache resume: the sender can resume missing ciphertext chunks only when the local wire cache, sanitized envelope header, saved key id/fingerprint, plaintext/wire hashes, and server resume metadata all match; missing or mismatched evidence fails closed to resend/clear.
- Encrypted file object/offline recovery evidence now has a fail-closed status surface plus verified filesystem, reviewed S3, and reviewed offline mirror ciphertext readback paths. Persisted recovery state may record a safe object key token, store type, ciphertext hash/size, sanitized envelope header, and material policy; when `QTNETWORKCHAT_OBJECT_ROOT` is configured and the filesystem object size/hash, envelope `ciphertextSha256`, current session key id/fingerprint, and server resume metadata all match, the sender can read back the object ciphertext and retransmit only missing encrypted chunks without reading the original plaintext file. S3 remains fail-closed by default, but an explicit `QTNETWORKCHAT_E2E_S3_OBJECT_RECOVERY_REVIEWED=1` opt-in plus normal S3 configuration allows reviewed S3 ciphertext readback after the safe object key, HEAD content length/hash metadata, verified GET body size/hash, envelope `ciphertextSha256`, current session key id/fingerprint, and server resume metadata all match. Offline mirror readback is also explicit: only `QTNETWORKCHAT_E2E_OFFLINE_OBJECT_RECOVERY_REVIEWED=1` plus `QTNETWORKCHAT_E2E_OFFLINE_OBJECT_RECOVERY_ROOT` lets a safe token map to a canonical file inside the configured mirror root; size/hash, envelope `ciphertextSha256`, current session key id/fingerprint, and server resume metadata must still match. Missing root, object loss, hash/header/session mismatch, S3/offline without reviewed opt-in, unsafe object locator, or server metadata mismatch remains fail-closed with fixed reasons and no endpoint, bucket, object URL, local root, local plaintext path, ciphertext bytes, or secret export. E2E recovery status exposes only the display filename for encrypted private files; plaintext/public saved-transfer status keeps the local path for UI recovery. Offline attachment replay now preserves the same sanitized E2E envelope header when chunking queued ciphertext, so receivers can reconstruct, authenticate, decrypt, and validate plaintext locally without server-side secret or plaintext access.
