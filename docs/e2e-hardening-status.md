# E2E Hardening Status

QtNetworkChat treats the server as a transparent carrier for private-message E2E envelopes, identity announcements, and rotation control messages. Trust decisions remain local to the client.

## Completed Boundaries

- Authenticated identity-bound agreement using signed request/response transcripts.
- Persistent local E2E identity material, observed peer fingerprints, trust pins, mismatch handling, and cross-device short-code verification.
- Default trust gates for private text and private files.
- History metadata migration for `plaintext`, `encrypted`, and `decrypt-failed` states.
- Private file payload encryption before chunk upload, including Redis/object routing evidence that avoids Redis plaintext or session keys.
- Encrypted private file same-wire cache resume: the sender can resume missing ciphertext chunks only when the local wire cache, sanitized envelope header, saved key id/fingerprint, plaintext/wire hashes, and server resume metadata all match; missing or mismatched evidence fails closed to resend/clear.
- Encrypted file object/offline recovery evidence now has a fail-closed status surface plus a verified filesystem object readback path. Persisted recovery state may record a safe object key token, store type, ciphertext hash/size, sanitized envelope header, and material policy; when `QTNETWORKCHAT_OBJECT_ROOT` is configured and the filesystem object size/hash, envelope `ciphertextSha256`, current session key id/fingerprint, and server resume metadata all match, the sender can read back the object ciphertext and retransmit only missing encrypted chunks without reading the original plaintext file. Missing root, object loss, hash/header/session mismatch, S3/offline auto-readback, or server metadata mismatch remains fail-closed with fixed reasons and no object URL, local root, ciphertext bytes, or secret export. Offline attachment replay now preserves the same sanitized E2E envelope header when chunking queued ciphertext, so receivers can reconstruct, authenticate, decrypt, and validate plaintext locally without server-side secret or plaintext access.

- Optional linked OpenSSL provider table now contains reviewed implementations for all eight provider operations: session-key generation uses OpenSSL RNG to produce a 32-byte handle-only sealed output, identity-key generation creates an Ed25519 seed and derives a 32-byte public output, public-key derivation derives a public output from an input seed, agreement sign/verify use Ed25519 over canonical transcripts, session derivation uses HKDF-SHA256 over canonical agreement/session context material, and payload encrypt/decrypt use AES-256-GCM with nonce/tag framing. Linked reviewed builds pass a runtime self-test that covers identity generation, public derivation, signing, verification, session derivation, payload encryption/decryption, and signature/ciphertext tamper rejection.
- When `QTNETWORKCHAT_E2E_LINK_PRODUCTION_ADAPTER=ON` and OpenSSL is found, `QTNETWORKCHAT_E2E_CRYPTO_BACKEND=production` or `openssl` now selects `openssl-reviewed-adapter-v1`, reports `productionReady=true`, and dispatches the public E2E API through the provider for session-key generation, identity-key generation, public-key derivation, agreement signing, signature verification, session derivation, payload encryption, and payload decryption. Local identity/session/trust-pin metadata records the selected production backend instead of the compiled draft backend.
- Linked reviewed builds now promote the sanitized provider invocation probe into the default production status surface: reviewed execution candidate, call handoff, operation stub, callable table bridge, callable interface, runtime preflight, invocation arming, execution acceptance, data-plane bridge, and public primitive execution evidence all show 8/8 ready when the OpenSSL provider has actually passed. In that linked path `productionAcceptance.accepted=true` and `releaseGate=production-crypto-accepted`; unlinked or self-test-failed paths still fail closed. Explicit probes still expose only size/status/material-policy/output-shape evidence and do not capture raw key/session/private identity/plaintext/ciphertext bytes.
- Production rollout observability is now a structured status surface. `productionRolloutObservability` summarizes the production acceptance release gate, material/export proof counts, public primitive readiness, no-sensitive-export proof, operator recovery prompts, user recovery prompts, filesystem object ciphertext readback readiness, and the remaining S3/offline auto-readback gap without exporting key material, session secrets, full public identities, plaintext bytes, ciphertext bytes, full fingerprints, or local private paths. It remains fail-closed until linked provider acceptance is complete, then reports `releaseGate=production-rollout-observability-ready`.
- Production rollout observability can now be persisted by `e2e_rollout_observability_exporter`. The tool writes sanitized JSON/Markdown evidence with release gates, counts, prompts, no-sensitive-export proof, filesystem object ciphertext readback status, and the S3/offline auto-readback gap only. Default CTest verifies the unlinked fail-closed evidence, and the linked OpenSSL runtime gate requires accepted evidence before the production adapter gate passes.
- Linked reviewed builds also verify production rotation execution through the client data plane: when dry-run gates all pass, `executeE2EProductionRotation` generates fresh production local identity material through the provider, persists the production backend id, clears old draft sessions and pending agreements, resets peer trust pins for re-verification, and emits only local rebind counts/fingerprint summaries. The runtime gate then drives Alice/Bob/Carol through multi-peer production identity re-announcement, cross-device-code re-verification, trust-pin rebind, independent signed production session rotation, encrypted private text delivery, and encrypted private file payload delivery on `openssl-reviewed-adapter-v1`. It also restarts all three clients with the same accounts, restores the persisted production identities and trust pins, refuses to reuse memory-only sessions, derives fresh independent signed production sessions, and repeats encrypted private text/file delivery. It does not export private keys, session keys, full public keys, plaintext, ciphertext, or full fingerprints.
